1. Media de cinco notas y aprobadoMedio

Lee cinco notas, muestra su media y escribe «Aprobado» si la media es 5 o más, o «Suspenso» si no.

Pista. Usa una variable suma que acumule las notas y un Para de 1 a 5. Después calcula la media dividiendo entre 5.

Ver soluciónMedia de cinco notas y aprobado
Proceso Notas
  Definir i, nota, suma, media Como Real
  suma<-0
  Para i<-1 Hasta 5 Hacer
    Escribir "Nota ", i, ": " Sin Saltar
    Leer nota
    suma<-suma+nota
  FinPara
  media<-suma/5
  Escribir "Media: ", media
  Si media>=5 Entonces
    Escribir "Aprobado"
  SiNo
    Escribir "Suspenso"
  FinSi
FinProceso
2. El mayor de tres númerosMedio

Lee tres números distintos y muestra cuál es el mayor.

Pista. Compara el primero con el segundo y el ganador con el tercero. Con Si y Sino Si puedes cubrir todos los casos.

Ver soluciónEl mayor de tres números
Proceso Mayor
  Definir a, b, c, m Como Real
  Leer a, b, c
  Si a>=b Y a>=c Entonces
    m<-a
  SiNo
    Si b>=c Entonces
      m<-b
    SiNo
      m<-c
    FinSi
  FinSi
  Escribir "El mayor es ", m
FinProceso
3. Contar pares hasta leer un 0Medio-difícil

Lee números enteros hasta que el usuario introduzca un 0. Al final muestra cuántos han sido pares. El 0 no cuenta.

Pista. El bucle debe leer antes de comprobar, así que una forma sencilla es leer un número fuera del bucle y otro dentro. Usa Mientras con la condición num<>0.

Ver soluciónContar pares hasta leer un 0
Proceso ContarPares
  Definir num, pares Como Entero
  pares<-0
  Escribir "Introduce un número (0 para acabar):"
  Leer num
  Mientras num<>0 Hacer
    Si num MOD 2 = 0 Entonces
      pares<-pares+1
    FinSi
    Leer num
  FinMientras
  Escribir "Pares: ", pares
FinProceso

Pista. Repetir Hasta se ejecuta al menos una vez, perfecto para validar. La condición de salida es que la nota esté entre 0 y 10.

    Leer nota

5. Calculadora con SegunMedio

Pide dos números y una opción: 1 suma, 2 resta, 3 multiplica, cualquier otra cosa muestra «Opción no válida».

Pista. Segun opcion Hacer … De Otro Modo … FinSegun. Recuerda que el Segun compara el valor de una sola variable.

Ver soluciónCalculadora con Segun
Proceso Calculadora
  Definir a, b, r Como Real
  Definir op Como Entero
  Leer a, b
  Escribir "1 suma, 2 resta, 3 multiplica:"
  Leer op
  Segun op Hacer
    1: r<-a+b
    2: r<-a-b
    3: r<-a*b
    De Otro Modo: Escribir "Opción no válida"
  FinSegun
  Escribir "Resultado: ", r
FinProceso

4. Errores típicos
  • Olvidar que el Segun compara una variable con varios valores, y Si con Y/O compara condiciones.
  • Usar = para asignar: en PSeInt la asignación es <- y la comparación es =.
  • Repetir Hasta cumple la condición al revés: el bucle sigue mientras la condición es falsa.
  • Dejar un contador sin inicializar (sin poner a 0 antes del bucle).
  • En diagramas, olvidar la flecha de vuelta al rombo de control del bucle.
  • Poner la lectura dentro del Mientras sin volver a leer al final (el bucle no avanza).
5. Ayudas y reglas nemotécnicas
Ciclo de vida

Análisis, Diseño, Codificación, Pruebas, Mantenimiento: «Ana Diseña Código, Prueba y Mantiene».

Cascada

Etapas en fila, como una cascada: no empiezas una hasta acabar la anterior. Con realimentación puedes volver atrás.

Incremental

«Incremento» = pequeñas partes que sirven. Entregas cada parte y la siguiente se suma a la anterior.

Espiral

Da vueltas y en cada vuelta mira los riesgos: «la espiral analiza riesgos».

Tipos de software

Sistema = hace funcionar el hardware (SO). Aplicación = tarea concreta (Word, CAD). Programación = herramientas para programar (IDE).

Shareware

«Share» = compartes para probar; luego pagas. Freeware = gratis, pero no modificar ni vender.

Adware

«Ad» = anuncio: se descarga publicidad al ejecutarse.

Software libre

Cuatro libertades: usar, estudiar, distribuir y mejorar. Necesita código fuente. Licencia típica: GPL.

Software propietario

«Propiedad»: se da en binario, sin código fuente, y el dueño prohíbe copiar o modificar.

Dominio público

«Es de todos»: sin licencia o autor desconocido; se puede usar libremente.

Nombres en Java

Clases con mayúscula (HiloServidor). Métodos camelCase (ejecutar). Constantes MAYÚSCULAS_CON_GUION. Paquetes en minúscula (java.io).

Formato Java

Sangría de 4 espacios, 80 caracteres por línea de código (70 en comentarios). Una variable por línea.

Comentarios Java

/** */ = documentación (va justo antes de la clase o método, lo lee Javadoc). /* */ y // = implementación.

Ficheros Java

Extensión .java al escribir y .class al compilar. Un solo public class por fichero, y debe ser la primera clase.

PSeInt: asignar y comparar

Asignar es <- (flecha que mete el valor). Comparar es = (signo igual). Definir x Como Real declara la variable.

PSeInt: MOD y DIV

MOD = resto (7 MOD 3 = 1). DIV = división entera (7 DIV 2 = 3). «MOD mira lo que sobra».

Mientras vs Repetir

Mientras comprueba antes (puede no entrar). Repetir comprueba después: entra al menos una vez.

Y / O

Y (AND) = tienen que cumplirse las dos. O (OR) = basta con una.

Diagramas: símbolos

Óvalo = inicio/fin (una pastilla). Rombo = decisión, dos salidas Sí/No. Rectángulo = proceso. Paralelogramo = entrada/salida de datos.

Diagramas: bucle

Si el rombo vuelve hacia atrás, es un bucle. Antes de volver, pon el contador a 0 y súmale en cada vuelta.

UT1 · Software, licencias y ciclo de vida

PDF «Apuntes UT1: Teoría y PSeInt», apartados 1 a 5
  • Hardware: componentes físicos que se pueden ver y tocar (monitor, teclado, placa base, RAM, microprocesador, disco duro).
  • Software: parte lógica. La RAE lo define como programas, instrucciones y reglas para ejecutar tareas en un ordenador. El IEEE 729 es más amplio: incluye también la documentación y los datos asociados.
  • Por tarea: software de sistema (SO, drivers, diagnóstico y optimización), de aplicación (ofimática, educativo, médico, contabilidad, CAD) y de programación (IDE, normalmente con GUI).
  • Por distribución: shareware (pruebas gratis un tiempo y luego pagas, p. ej. WinRAR), freeware (sin coste, pero no se puede modificar ni vender), adware (gratis con publicidad que desaparece al comprar la licencia), multimedia y de uso específico (hecho para un problema concreto de una organización).
  • Licencia: contrato que fija los derechos y deberes de desarrollador y usuario. Ejemplo: el contrato de usuario final que aceptas al instalar un antivirus.
  • Software libre: cuatro libertades (usar, estudiar, distribuir y mejorar). Para estudiarlo y mejorarlo hace falta el código fuente. Licencia más usada: GPL. Si distribuyes una versión modificada, debe publicarse con su código y bajo la misma licencia; si solo la usas en privado, no hay obligación de publicarla.
  • Software propietario: se distribuye en binario (compilado, sin código fuente). Prohíbe redistribuir, modificar, copiar o usar en varios equipos sin permiso.
  • Dominio público: sin licencia o con autor desconocido. Cualquiera puede usarlo, incluso para crear productos propietarios.
  • Ciclo de vida (ISO/IEC 12207-1): marco que recoge los procesos desde la definición de requisitos hasta el fin de uso. Cinco etapas: análisis, diseño, codificación, pruebas y mantenimiento. Cada etapa recibe los documentos de la anterior y genera otros nuevos.
  • Cascada: etapas en orden estricto y revisión al final de cada una. Su variante con realimentación permite volver a una etapa anterior. Ventajas: fácil de planificar y de alta calidad. Inconvenientes: exige requisitos fijados desde el principio y el producto no se ve hasta el final. Se recomienda si el proyecto es parecido a otro ya hecho y los requisitos son estables.
  • Incremental: repite ciclos en cascada y entrega partes pequeñas pero utilizables (incrementos). Ejemplo: un procesador de textos con funciones básicas, luego corrector y luego paginación. Inconvenientes: difícil estimar coste y riesgo de no terminar. No recomendable en tiempo real ni en sistemas de alta seguridad.
  • Espiral: combina cascada y prototipos. Cada vuelta incluye determinar objetivos, evaluar alternativas y analizar riesgos, desarrollar y probar, y planificar la siguiente. Se recomienda en proyectos grandes con cambios constantes.
RecuerdaFreeware no es software libre (gratis pero cerrado). Solo la espiral incorpora análisis de riesgos en cada vuelta. Casi todos los ciclos pasan por análisis y diseño antes de codificar.

UT1 · Fases, lenguajes, compilación, JVM y normas Java

PDF «Apuntes UT1: Teoría y PSeInt», apartados 6 a 11 y 13
  • Fases del desarrollo: análisis, diseño, codificación, pruebas, documentación, explotación y mantenimiento.
  • Análisis (¿qué hay que hacer?): requisitos funcionales (qué hace el sistema) y no funcionales (fiabilidad, plataforma, restricciones). Técnicas: entrevistas, JAD/JRP, brainstorming, prototipos y casos de uso. Herramientas: DFD (flujo de datos), DFC (flujo de control), DTE (transición de estados), DER (entidad-relación) y diccionario de datos.
  • Diseño (¿cómo se resuelve?): estructurado, con cuatro elementos (datos, arquitectura, interfaz y procedimientos), o orientado a objetos, con UML y cuatro capas (responsabilidades, mensajes, clases y objetos, subsistemas). Los componentes se diseñan con secuencia, condición y repetición.
  • Codificación: el diseño se convierte en código fuente. Luego el compilador genera el objeto y el enlazador el ejecutable.
  • Pruebas: verificación (¿lo construimos bien?) y validación (¿construimos lo que pidió el cliente?). Caso de prueba: entradas, salida esperada y condiciones previas. Una prueba tiene éxito si descubre un error. Caja blanca (estructura interna) y caja negra (solo entradas y salidas).
  • Documentación: de proceso (planes, horarios, normas) y de producto (técnica para el sistema y de usuario). La de usuario incluye la descripción funcional, el documento de instalación, el manual introductorio, el de referencia y la guía del administrador.
  • Explotación: implantación en el entorno del cliente, pruebas de operación de cada versión y soporte al usuario.
  • Mantenimiento (IEEE 1219): correctivo (fallos), adaptativo (cambios del entorno, el más habitual), perfectivo (mejoras y nuevas funciones) y preventivo (facilitar el mantenimiento futuro; incluye la reingeniería).
  • Von Neumann: programa y datos en la misma memoria. CPU con unidad de control, UAL y registros de trabajo. Registros de la UC: CP (siguiente instrucción), RI (instrucción actual), RDM (dirección de memoria) y RIM (dato leído o escrito). Cada instrucción tiene fase de búsqueda (fetch) y de ejecución (execute).
  • Lenguajes: léxico (símbolos), sintaxis (cómo combinarlos) y semántica (su significado). Por nivel: máquina (ceros y unos), ensamblador, medio (C) y alto (Java, Python, C++). Por paradigma: imperativo, funcional, lógico, estructurado, modular y orientado a objetos.
  • Compilador traduce todo el programa; si hay errores no genera código objeto. Intérprete traduce y ejecuta instrucción a instrucción. Java combina ambos: .java → bytecode (.class) → JVM.
  • Código fuente → objeto → ejecutable. Fases del compilador: léxico (tokens), sintáctico, semántico (tipos y declaraciones) y generación y optimización de código.
  • JVM: máquina virtual de proceso. Reserva y libera memoria, se comunica con el SO y vela por la seguridad. VirtualBox es una máquina virtual de sistema.
  • Normas Java (apartado 11): un fichero con una sola clase pública, que es la primera; orden: comentario inicial, package, import y clase. Sangría de cuatro espacios; líneas de hasta 80 caracteres (70 en comentarios). Una variable por línea; bloques siempre entre llaves; return total; sin paréntesis; dos líneas en blanco entre clases y una entre métodos.
  • Nombres: paquetes en minúsculas (java.io); clases con mayúscula inicial (HiloServidor); métodos y variables en camelCase (asignarDestino()); constantes en MAYÚSCULAS_CON_GUION_BAJO (MAX_VALOR).
RecuerdaVerificación frente a validación; caja blanca frente a caja negra; compilador frente a intérprete; y en Java, import java.io.*; con asterisco.

PSeInt y diagramas de flujo

PDF «Apuntes UT1: Teoría y PSeInt», apartados 14 a 21
  • Algoritmo: secuencia ordenada, precisa, definida y finita. Esquema entrada → proceso → salida. Puede escribirse en pseudocódigo o dibujarse como diagrama de flujo (ordinograma). PSeInt convierte uno en otro.
  • Perfil Estricto (Configurar → Opciones del lenguaje): obliga a declarar con Definir antes de usar; dar valor antes de consultar; terminar cada instrucción con punto y coma; usar Segun solo con valores numéricos; empezar los arreglos en 0.
  • Símbolos del diagrama: terminal (inicio y fin, uno de cada), proceso (Definir, asignaciones, cálculos), entrada (Leer), salida (Escribir), decisión Si (dos salidas V y F), selección múltiple Segun, condición de bucle, bucle Para y línea de flujo.
  • Buen diagrama: un único inicio y un único fin; avanza de arriba abajo; etiqueta V y F en cada decisión; vuelve a unir las ramas; no deja ningún bloque sin salida.
  • Datos: Definir x Como Entero / Real / Logico / Caracter. Constantes, operadores aritméticos (+ − * / ^ MOD y paréntesis) y de comparación (= <> < > <= >=). Lógicos: Y (ambas), O (una) y NO (invierte). Asignación con <-.
  • Escribir y Leer: el texto va entre comillas; Escribir edad; muestra el valor y Escribir "edad"; la palabra. Leer guarda lo que escribe el usuario. Antes de cada Leer, un Escribir con la pregunta exacta del enunciado.
  • Condicionales: Si … Entonces … SiNo … FinSi (el SiNo es opcional). Segun … De Otro Modo … FinSegun para varias opciones.
  • Bucles: Mientras comprueba antes (puede hacer 0 vueltas); Repetir … Hasta Que comprueba después (al menos 1); Para i <- 1 Hasta n Con Paso p Hacer cuando conoces el número de vueltas.
  • Patrones: contador (a 0 antes del bucle, suma 1); acumulador (a 0 antes, suma cantidades); bandera (variable lógica que recuerda un suceso; para validar varios datos con un único mensaje de error); validación con Repetir; lectura adelantada con centinela (lees antes del Mientras y al final del cuerpo); pregunta «¿otra vez?» con Repetir.
  • Arreglos y matrices: Dimension notas[3] guarda varios valores del mismo tipo con un nombre y un índice. Una matriz tiene dos índices: Dimension tabla[2,3] crea 2 filas y 3 columnas.
  • Subprocesos: agrupan instrucciones con nombre para llamarlas desde el principal. Pueden recibir parámetros (por valor: copia; por referencia: modifican la original) y devolver un valor.
  • Método: entender el enunciado; identificar datos de entrada, cálculos y salida; escribir primero las variables; construir por partes; probar con valores sencillos y con casos límite.
RecuerdaTraza: anota cómo cambia cada variable en cada vuelta. Al sumar 6, 8 y 10 con un acumulador, la suma pasa por 0, 6, 14 y 24.
9. PSeInt desde cero hasta algoritmia avanzada

Guía de PSeInt para el examen: desde variables y condicionales hasta vectores, matrices, funciones, búsqueda y ordenación.

Método para cualquier ejercicioBase
PasoPregunta que debes hacerte
1. Entender¿Qué me pide exactamente el enunciado?
2. Entrada¿Qué datos tengo que pedir o recibir?
3. Variables¿Qué nombres y tipos de datos necesito?
4. Proceso¿Qué cálculos, comparaciones o repeticiones hacen falta?
5. Salida¿Qué resultado debo mostrar?
6. Prueba¿Funciona con datos normales y con casos límite?

Idea clave. Casi todos los ejercicios son: entrada (datos), proceso (operaciones) y salida (resultados).

Un algoritmo es una secuencia ordenada y finita de pasos. Debe ser preciso, definido (mismos datos, mismo resultado) y finito.

Primer programa, variables, Leer y EscribirBase

Un programa mínimo:

Algoritmo MiPrimerPrograma
    Escribir "Hola, mundo"
FinAlgoritmo
InstrucciónSignificado
AlgoritmoMarca el comienzo y da nombre al programa.
EscribirMuestra un texto o un valor en pantalla.
FinAlgoritmoMarca el final.

Variable: un espacio con nombre que guarda un dato, que puede cambiar. Definir edad Como Entero la crea; edad <- 30 le asigna un valor.

TipoQué almacenaEjemplos
EnteroNúmeros sin parte decimal5, 20, -3
RealNúmeros con decimales3.5, 8.75
CaracterTexto"Alba", "Hola"
LogicoVerdadero o FalsoVerdadero

Regla rápida: edad suele ser Entero; precio suele ser Real; nombre suele ser Caracter; sí/no suele ser Logico.

Leer guarda lo que escribe el usuario. Antes de cada Leer conviene un Escribir con la pregunta.

Algoritmo SumarDosNumeros
    Definir numero1, numero2, resultado Como Real
    Escribir "Introduce el primer numero:"
    Leer numero1
    Escribir "Introduce el segundo numero:"
    Leer numero2
    resultado <- numero1 + numero2
    Escribir "La suma es: ", resultado
FinAlgoritmo

Ejemplo resuelto: si introduces 5 y 8, muestra 13.

En pseudocódigo

Se declara con Definir, se asigna con <-, se pide con Escribir seguido de Leer, y se muestra con Escribir.

En diagrama de flujo

[ Inicio ]
     |
[ Definir numero1, numero2, resultado Como Real ]
     |
[ Escribir "Introduce el primer numero:" ]   (salida)
[ Leer numero1 ]                              (entrada)
     |
[ resultado <- numero1 + numero2 ]            (proceso)
     |
[ Escribir "La suma es: ", resultado ]        (salida)
     |
[ Fin ]

Un Escribir va antes de cada Leer, y la pregunta debe coincidir con la del enunciado. Cada bloque es un símbolo distinto.

En el diagrama, MOD y las comparaciones van dentro del rombo; el resultado se ve en la rama V o F.

Condicionales: Si, SiNo y SegunMedio

El condicional ejecuta unas instrucciones si se cumple una condición y otras si no.

Algoritmo MayorEdad
    Definir edad Como Entero
    Escribir "Introduce tu edad:"
    Leer edad
    Si edad >= 18 Entonces
        Escribir "Eres mayor de edad"
    SiNo
        Escribir "Eres menor de edad"
    FinSi
FinAlgoritmo

Cada Si se cierra con su propio FinSi. Con varios anidados, cuenta aperturas y cierres.

Algoritmo Calificacion
    Definir nota Como Real
    Escribir "Introduce la nota:"
    Leer nota
    Si nota < 0 O nota > 10 Entonces
        Escribir "Nota no valida"
    SiNo
        Si nota < 5 Entonces
            Escribir "Suspenso"
        SiNo
            Si nota < 7 Entonces
                Escribir "Aprobado"
            SiNo
                Si nota < 9 Entonces
                    Escribir "Notable"
                SiNo
                    Escribir "Sobresaliente"
                FinSi
            FinSi
        FinSi
    FinSi
FinAlgoritmo

Recuerda: Si sirve para evaluar condiciones; Segun sirve para elegir entre opciones o casos.

Segun sirve para un menú. Ejemplo: una calculadora.

Algoritmo Calculadora
    Definir opcion Como Entero
    Definir a, b Como Real
    Escribir "1. Sumar"
    Escribir "2. Restar"
    Escribir "3. Multiplicar"
    Escribir "4. Dividir"

            Escribir a + b
        2:

            SiNo

            FinSi
        De Otro Modo:

    FinSegun

En pseudocódigo

Si … Entonces … SiNo … FinSi para dos caminos. Segun … De Otro Modo … FinSegun para varias opciones.

En diagrama de flujo

   V /         \ F
[ Escribir "Mayor" ] [ Escribir "Menor" ]
   \         /
   [ siguiente paso ]

[ suma ] [ resta ] [ producto ] [ "Opcion incorrecta" ]

   [ siguiente paso ]

Cada rama termina en el mismo punto de unión. Las decisiones siempre tienen V y F o, en Según, una salida por opción.

Números primosDifícil

Un primo es un entero mayor o igual que 2 que solo tiene dos divisores positivos: 1 y él mismo. 2, 3, 5 y 7 son primos; 9 no, porque también es divisible entre 3.

Idea: probar divisores desde 2 hasta la raíz cuadrada del número.

Algoritmo NumeroPrimo
    Definir numero, i Como Entero
    Definir primo Como Logico
    Escribir "Introduce un numero:"
    Leer numero
    primo <- Verdadero
    Si numero < 2 Entonces
        primo <- Falso
    SiNo
        Para i <- 2 Hasta RC(numero) Hacer
            Si numero MOD i = 0 Entonces
                primo <- Falso
            FinSi
        FinPara
    FinSi
    Si primo Entonces
        Escribir "Es primo"
    SiNo
        Escribir "No es primo"
    FinSi
FinAlgoritmo

En pseudocódigo

Se usa un Para desde 2 hasta RC(numero) y un Si con MOD dentro.

En diagrama de flujo

[ Leer numero ]
[ primo <- Verdadero ]
< numero < 2 ? >  V -> [ primo <- Falso ]
     | F
[ Para i <- 2 Hasta RC(numero) ]
     |
< numero MOD i = 0 ? >  V -> [ primo <- Falso ]
     | F
     |  (vuelve al símbolo Para)
< primo ? >  V -> [ Escribir "Es primo" ]   F -> [ Escribir "No es primo" ]

El Para queda dentro del flujo y el Si con MOD dentro del bucle. La salida depende del valor de primo al final.

Ecuaciones de segundo gradoDifícil

Forma: ax² + bx + c = 0 (a no puede ser 0). Primero el discriminante D = b² − 4ac:

DiscriminanteSoluciones reales
D > 0Dos soluciones distintas
D = 0Una solución doble
D < 0Ninguna real

Ejemplo: x² − 5x + 6 = 0 → a = 1, b = −5, c = 6 → D = 25 − 24 = 1 → x1 = 3 y x2 = 2.

Algoritmo EcuacionSegundoGrado
    Definir a, b, c, discriminante, x1, x2 Como Real
    Escribir "Introduce el valor de a:"
    Leer a
    Escribir "Introduce el valor de b:"
    Leer b
    Escribir "Introduce el valor de c:"
    Leer c
    Si a = 0 Entonces
        Escribir "No es una ecuacion de segundo grado"
    SiNo
        discriminante <- b^2 - 4*a*c
        Si discriminante > 0 Entonces
            x1 <- (-b + RC(discriminante)) / (2*a)
            x2 <- (-b - RC(discriminante)) / (2*a)
            Escribir "Primera solucion: ", x1
            Escribir "Segunda solucion: ", x2
        SiNo
            Si discriminante = 0 Entonces
                x1 <- -b / (2*a)
                Escribir "Solucion doble: ", x1
            SiNo
                Escribir "No existen soluciones reales"
            FinSi
        FinSi
    FinSi
FinAlgoritmo

Comprueba siempre que a <> 0 antes de dividir entre 2a.

En pseudocódigo

Se calcula el discriminante con ^ y RC, y después se elige la rama según D sea mayor, igual o menor que 0, con un Si anidado.

En diagrama de flujo

[ Leer a, b, c ]
< a = 0 ? >   V -> [ Escribir "No es de segundo grado" ]
   | F
[ discriminante <- b^2 - 4*a*c ]
< discriminante > 0 ? >
  V |                   F |
[ x1 y x2 con RC ]   < discriminante = 0 ? >
                        V |          F |
                 [ x1 = -b/(2a) ]  [ Escribir "No existen soluciones reales" ]

Las comprobaciones de a y de D son decisiones en cascada. Cada rama termina en su propia salida.

Una matriz tiene dos dimensiones (filas y columnas) y se accede con dos índices: notas[2,1] es fila 2, columna 1. Un bucle dentro de otro se llama bucle anidado: el primero recorre las filas y el segundo las columnas.

        FinPara
    FinPara
FinAlgoritmo

Búsqueda y ordenación (burbuja)Difícil

Búsqueda secuencial: recorre los elementos uno a uno hasta encontrar el valor o llegar al final. Funciona aunque el vector no esté ordenado.

Algoritmo Busqueda
    Definir numeros Como Entero
    Definir i, buscado, posicion Como Entero
    Dimension numeros[5]
    Para i <- 1 Hasta 5 Hacer
        Escribir "Introduce un numero:"
        Leer numeros[i]
    FinPara
    Escribir "Numero que quieres buscar:"
    Leer buscado
    posicion <- 0
    Para i <- 1 Hasta 5 Hacer
        Si numeros[i] = buscado Entonces
            posicion <- i
        FinSi
    FinPara
    Si posicion <> 0 Entonces
        Escribir "Encontrado en posicion: ", posicion
    SiNo
        Escribir "No encontrado"
    FinSi
FinAlgoritmo

Burbuja: compara vecinos e intercambia si están desordenados; repite pasadas hasta dejarlo ordenado. AUX es una variable temporal que evita perder un valor al intercambiar. Ejemplo: guardas 5 en aux, pones 2 en la primera posición y recuperas 5 para la segunda. [5, 2] → [2, 5].

Algoritmo OrdenarBurbuja
    Definir numeros Como Entero
    Definir i, j, aux Como Entero
    Dimension numeros[4]
    Para i <- 1 Hasta 4 Hacer
        Escribir "Introduce un numero:"
        Leer numeros[i]
    FinPara
    Para i <- 1 Hasta 3 Hacer
        Para j <- 1 Hasta 4-i Hacer
            Si numeros[j] > numeros[j+1] Entonces
                aux <- numeros[j]
                numeros[j] <- numeros[j+1]
                numeros[j+1] <- aux
            FinSi
        FinPara
    FinPara
    Escribir "Numeros ordenados:"
    Para i <- 1 Hasta 4 Hacer
        Escribir numeros[i]
    FinPara
FinAlgoritmo

En pseudocódigo

La búsqueda recorre el vector con un Para y un Si. La burbuja usa dos Para anidados y un intercambio con aux.

En diagrama de flujo

BÚSQUEDA                            BURBUJA
[ posicion <- 0 ]                    [ Para i <- 1 Hasta 3 ]
[ Para i <- 1 Hasta 5 ]             [ Para j <- 1 Hasta 4-i ]
     |                                  |
< numeros[i] = buscado ? >          < numeros[j] > numeros[j+1] ? >
  V -> [ posicion <- i ]              V |
     |  (vuelve)                  [ aux <- numeros[j] ]
[ Si posicion <> 0 ... ]           [ numeros[j] <- numeros[j+1] ]
                                    [ numeros[j+1] <- aux ]

La decisión decide si hay intercambio. El AUX es el paso intermedio: sin él se pierde un valor.

Errores frecuentes en el examenImportante
  • Confundir asignación y comparación: <- asigna; = compara.
  • Olvidar definir una variable antes de usarla.
  • Usar Entero cuando el dato puede tener decimales.
  • No inicializar un acumulador en 0 (o un producto en 1).
