1. Introducción

Casi cualquier documento que un programa envía, guarda o intercambia (una página web, un fichero de configuración, los datos de una tienda) necesita una estructura reconocible por personas y máquinas. Los lenguajes de marcas resuelven ese problema. Esta unidad tiene dos partes: una introducción a la familia (qué son, clasificación, historia, HTML, XML y Markdown) y XML, el más importante de la asignatura: estructura, sintaxis y reglas de un documento correcto.

2. Qué es un lenguaje de marcado

Es un conjunto de reglas para combinar el texto de un documento con marcas (etiquetas) que añaden información sobre ese texto: su estructura, su significado o su presentación. La marca no es el contenido, sino una anotación sobre él; en XML y HTML va entre < y >. Suelen aparecer por parejas, apertura y cierre.

<titulo>El ingenioso hidalgo don Quijote de la Mancha</titulo>

Un programa sabe que ese texto es un título solo reconociendo la etiqueta, sin «entender» español.

Un sistema de codificación

Detrás de cualquier lenguaje de marcado hay un sistema de codificación: reglas para representar datos y caracteres de forma que una computadora los interprete y procese, no solo los muestre. Define cómo se asigna cada símbolo a una secuencia de bits.

Marcado y programación

Un lenguaje de marcado no es un lenguaje de programación: no tiene variables, bucles ni operaciones; describe la estructura. Se combinan con normalidad (un HTML incluye JavaScript, un XML se procesa con Python o Java). El lenguaje debe ser independiente de quien lo interprete: el intérprete decide cómo representar las marcas. Por eso una misma página se ve algo distinta según el navegador.

3. Metalenguaje

Un metalenguaje es un lenguaje que sirve para definir otros lenguajes: no fija un conjunto cerrado de etiquetas, sino las reglas para crear las propias.

  • SGML y XML son metalenguajes.
  • HTML no lo es: es un lenguaje concreto con un vocabulario cerrado (<p>, <table>, <img>…), definido en su día con SGML y luego con XML (XHTML).

Si XML es la gramática que permite crear idiomas, HTML es un idioma concreto ya escrito con ella.

  • Anidamiento: loc está dentro de url, y url dentro de urlset.
  • Atributos: xmlns en urlset.

4. Clasificación de los lenguajes de marcas

De presentación (o de procedimiento)

Las marcas indican cómo debe mostrarse el texto: negrita, tamaño, color. Ejemplo histórico: RTF. Limitación: mezclan contenido y formato, lo que dificulta reutilizar la información.

{\rtf1\ansi Este texto tiene \b una palabra en negrita\b0  y el resto en normal. }

\b y \b0 activan y desactivan la negrita: para RTF lo mismo que <b> y </b> para HTML.

Descriptivos (o declarativos)

Las marcas describen qué es cada parte del contenido, no su aspecto. XML es el ejemplo de referencia. Ventaja: el mismo documento puede presentarse de formas distintas.

<libro>
  <titulo>El Quijote</titulo>
  <autor>Cervantes</autor>
</libro>

Híbridos

Combinan ambos enfoques. HTML es el ejemplo típico: etiquetas descriptivas (<h1>, <p>, <table>) y, sobre todo en versiones antiguas, de presentación (<b>, <font>, align="center"). Las versiones modernas delegan la presentación en CSS.

5. Origen y evolución: de GML a HTML y XML

AñoHito
Años 70IBM desarrolla GML (Generalized Markup Language)
1986La ISO estandariza SGML (ISO 8879), metalenguaje sucesor de GML
1989-1991Tim Berners-Lee crea HTML como aplicación concreta de SGML
1998El W3C publica XML 1.0, simplificación de SGML pensada para la Web
  • GML (años 70, IBM): nació por la falta de compatibilidad entre aplicaciones, cada una con sus marcas. Lo desarrollaron Charles Goldfarb, Edward Mosher y Raymond Lorie (sus iniciales dan nombre al lenguaje). Independizaba el documento del dispositivo y usaba marcas descriptivas.
  • SGML (1986): no es un lenguaje, sino un metalenguaje (ISO 8879). Muy potente pero complejo; se usó en editoriales, administraciones e industria aeronáutica.
  • HTML (1989-1991): aplicación concreta de SGML con un vocabulario ya cerrado, pensado para hipertexto.
  • XML (1998): SGML era demasiado complejo para la Web y HTML demasiado rígido (no permitía etiquetas propias). XML conserva lo esencial de SGML, simplificado, para que lo procesen máquinas y lo lean personas, orientado al intercambio de datos entre sistemas.

6. HTML, XML y Markdown

HTML

Lenguaje de marcado más conocido para crear páginas web: define títulos, párrafos, imágenes, enlaces… Se ve en profundidad en la Unidad 2.

<h1>Título del artículo</h1>
<p>Este es un párrafo de ejemplo.</p>
<h2>Listado de elementos:</h2>
<ul>
  <li>Encabezados</li>
  <li>Párrafos</li>
  <li>Listas</li>
</ul>

Para ver el HTML real de una página: clic derecho → «Ver código fuente» (o Ctrl+U).

XML

XML (Extensible Markup Language) estructura y almacena datos de forma jerárquica. A diferencia de HTML, no tiene etiquetas predefinidas: quien escribe el documento decide qué etiquetas usar.

<?xml version="1.0" encoding="UTF-8"?>
<profesor>
  <nombre>Andrea</nombre>
  <apellidos>Lluch Cruz</apellidos>
  <fecha-de-nacimiento>
    <dia>28</dia>
    <mes>2</mes>
    <año>2030</año>
  </fecha-de-nacimiento>
</profesor>

Markdown

Lenguaje de marcado ligero con sintaxis mínima: basta un símbolo al principio de una línea o rodear una palabra con asteriscos para obtener un encabezado, una negrita o una lista. Lo usan WordPress, GitHub (README) y herramientas de documentación técnica.

# Título del artículo
Este es un párrafo de ejemplo.
## Listado de elementos:
- Encabezados
- Párrafos
- Listas

Los tres ejemplos describen el mismo contenido con tres sintaxis distintas: tienen en común marcar la estructura y se diferencian en cómo.

7. XML: estructura y sintaxis

Un documento XML se construye con tres piezas: elementos (etiqueta de apertura y de cierre, con texto u otros elementos anidados), atributos (pares nombre="valor" en la etiqueta de apertura) y valores. El resultado es un árbol con un único elemento raíz.

<?xml version="1.0" encoding="UTF-8"?>
<biblioteca>
    <libro idioma="es">
        <titulo>El Quijote</titulo>
        <autor>Miguel de Cervantes</autor>
    </libro>
</biblioteca>

Aquí: raíz biblioteca, hijo libro con el atributo idioma, y dos elementos de texto.

8. Reglas de un XML bien formado

Para que un programa lo lea sin errores, el documento debe estar bien formado:

  • Un único elemento raíz.
  • Toda etiqueta que se abre debe cerrarse.
  • Las etiquetas no pueden cruzarse.
  • El valor de un atributo va siempre entre comillas.
  • XML distingue mayúsculas de minúsculas: <Libro> y <libro> son distintas.
✔ Correcto:    <a><b>texto</b></a>
✘ Incorrecto:  <a><b>texto</a></b>      (las etiquetas se cruzan)

✘ Incorrecto:  <telefono>600123456
✔ Correcto:    <telefono>600123456</telefono>

Bien formado no es lo mismo que válido: un documento válido, además, cumple un esquema (DTD o XSD) que fija qué elementos puede tener y en qué orden (unidad posterior).

9. Espacios de nombres (namespaces)

Dos documentos pueden usar la misma etiqueta con significados distintos (<titulo> de un libro o de una película). Los namespaces evitan la ambigüedad asociando un prefijo a cada vocabulario con el atributo xmlns.

<biblioteca
    xmlns:libro="http://ejemplo.org/libros"
    xmlns:pelicula="http://ejemplo.org/peliculas">

    <libro:titulo>El Quijote</libro:titulo>
    <pelicula:titulo>El Quijote (1992)</pelicula:titulo>
</biblioteca>

10. Ventajas de XML

  • Es extensible: se pueden añadir etiquetas nuevas sin rehacer lo ya construido.
  • Se procesa con un analizador (parser) estándar: sirve para cualquier XML bien formado, sin programa distinto para cada vocabulario.
  • Mejora la compatibilidad entre aplicaciones: sin importar la plataforma (p. ej. una aplicación en Linux con PostgreSQL y otra en Windows con SQL Server).
  • Transforma datos en información: cada dato lleva un significado y un contexto mediante su etiqueta, y el mismo documento se puede estructurar de formas distintas.

11. Herramientas de edición y visualización

Un XML es texto plano: sirve cualquier editor.

  • Editores genéricos con resaltado de sintaxis: Visual Studio Code, Notepad++, Sublime Text.
  • Editores XML especializados con validación: Oxygen XML Editor, XMLSpy.
  • Navegadores (Chrome, Firefox…): muestran el .xml en vista de árbol.
  • Librerías de los lenguajes de programación para leer y generar XML.

LenguajeQué resuelveSe estudia en

  • HTML: lenguaje híbrido que define qué es cada parte de la página.
  • CSS (Cascading Style Sheets): no es un lenguaje de marcas (no usa < >), pero define el aspecto visual de lo que HTML marca; separa contenido y presentación.
h2 {
  color: #1F4E79;
  font-size: 1.5rem;
}
  • JavaScript: lenguaje de programación completo, con variables, condicionales, bucles y funciones; da comportamiento a la página y se usa para leer y generar JSON.
document.querySelector("h2").textContent = "Servicios actualizados";
  • JSON (JavaScript Object Notation): tampoco es un lenguaje de marcas; usa pares clave-valor entre llaves y cumple el mismo papel que XML con una sintaxis más ligera.
{
  "nombre": "Andrea",
  "apellidos": "Lluch Cruz",
  "fechaNacimiento": { "dia": 28, "mes": 2, "anio": 2030 }
}

Ideas clave

  • Un lenguaje de marcado combina contenido y marcas que aportan información sobre él; no es un lenguaje de programación.
  • Se clasifican en de presentación, descriptivos e híbridos.
  • GML (IBM, años 70) → SGML (ISO, 1986), el metalenguaje del que nacieron HTML (1989-1991) y XML (W3C, 1998).
  • HTML, XML y Markdown: mismo objetivo, sintaxis distintas.
  • XML: elementos, atributos y valores, en árbol con un único elemento raíz; ser válido exige además cumplir un esquema (DTD o XSD).
  • Los namespaces evitan la ambigüedad entre etiquetas del mismo nombre.
  • El resto de la asignatura gira en torno a HTML, CSS, JavaScript y JSON.
